# 5.1 응용 계층의 개요

응용 계층은 TCP/IP 모델의 최상위 계층으로, 사용자가 네트워크를 통해 원하는 작업을 수행할 수 있도록 애플리케이션이 작동하는 계층이다. <br>
애플리케이션 간 통신을 위한 데이터 형식, 전송 방법, 오류 처리 방식 등을 정의하고 사용자가 입력한 정보(검색어, 이메일, 파일 등)를 각 애플리케이션의 형식에 맞게 전송 계층으로 전달하는 역할을 한다.<br>
전송 계층이 데이터를 캡슐화하고 TCP 또는 UDP 중 적절한 프로토콜로 전송하면 응용 계층은 포트 번호를 직접 다루지 않지만, 전송 계층의 포트 번호를 통해 애플리케이션을 구분한다.<br>

자주 사용되는 응용 계층 프로토콜을 5개의 카테고리로 나눌 수 있다.
- 관리용 프로토콜: 네트워크 장비나 서버의 상태를 모니터링하고 관리한다. 
- 원격 접속 프로토콜: 원격지에 있는 시스템에 접속해 시스템을 제어하고 관리한다. 
- 파일 전송 프로토콜: 네트워크를 통해 파일을 업로드 및 다운로드한다. 
- 이메일 프로토콜: 이메일을 송수신하고 저장 및 관리한다. 
- 웹 브라우저 프로토콜: 웹 페이지를 요청하고 받아온다.

# 5.2 관리용 프로토콜

<img width="600" height="250" alt="image" src="https://cf-assets.www.cloudflare.com/slt3lc6tev37/1NzaAqpEFGjqTZPAS02oNv/bf7b3f305d9c35bde5c5b93a519ba6d5/what_is_a_dns_server_dns_lookup.png" /> <br>

__DNS(Domain Name System)__ 는 도메인 이름을 IP 주소로 변환하거나 그 반대로 IP 주소를 도메인 이름으로 변환(역방향 조회)하는 역할을 한다.
기본적으로 UDP 53번 포트를 사용하며, 필요할 경우 TCP 53번 포트를 이용한다.<br>
작동 과정은 다음과 같다. 사용자가 웹 브라우저에 google.com과 같은 도메인 이름을 입력하면, DNS 서버가 해당 도메인에 대응하는 IP 주소를 찾아 반환하고, 브라우저는 그 IP 주소를 이용해 실제 웹 서버에 접속한다. 이러한 방식 덕분에 사용자는 복잡한 IP 주소를 외울 필요 없이 도메인 이름만으로 쉽게 접속할 수 있으며, 서버의 IP가 변경되더라도 DNS 서버 정보만 갱신하면 자동으로 반영된다.<br>
DNS는 웹 접속, 이메일 인증(역방향 조회), 네트워크 관리, 보안 분석 등 다양한 분야에서 활용된다.<br>

__DHCP(Dynamic Host Configuration Protocol)__ 는 네트워크에 연결된 장치에 IP 주소와 관련 설정(서브넷 마스크, 게이트웨이, DNS 등) 을 자동으로 할당하는 프로토콜이다. <br>
전송 계층에서 UDP 67번(서버)·68번(클라이언트) 포트를 사용하며, 수동 설정 없이도 장치가 네트워크에 쉽게 연결되도록 해 관리자의 부담을 줄이고 사용자 편의성을 높인다.<br>

__NTP(Network Time Protocol)__ 는 네트워크 장치의 시간을 NTP 서버와 동기화해 정확한 시간을 유지하도록 하는 프로토콜이다. <br>
UDP 123번 포트를 사용하며, 시스템 시간이 어긋날 경우 로그 기록 오류, 인증 실패, 예약 작업 실패 등의 문제가 발생할 수 있다. 따라서 NTP는 분산 환경에서 모든 시스템의 시간 일관성을 보장하는 핵심 프로토콜이다.<br>

<img width="600" height="200" alt="image" src="https://itwiki.kr/images/0/04/SNMP.png" /> <br>
__SNMP(Simple Network Management Protocol)__ 는 라우터, 스위치, 서버, 프린터 등 네트워크 장비를 중앙에서 모니터링하고 제어하기 위한 프로토콜이다. <br>
관리 스테이션(NMS) 과 관리 대상 장치(에이전트) 로 구성되며, NMS가 각 장치의 상태(메모리, CPU, 대역폭 등)를 수집하고 설정을 제어한다. <br>
기본적으로 UDP 161번 포트를 사용하며, 장치가 이상 상황을 보고할 때는 162번 포트로 트랩(trap) 메시지를 전송한다.<br>

__LDAP(Lightweight Directory Access Protocol)__ 는 디렉터리 서비스에 접근해 정보 검색·수정이 가능하게 하는 프로토콜로, TCP 389번 포트를 사용한다.<br>
디렉터리 서비스는 조직 내 사용자 정보, 자원 위치, 인증/권한 관리 정보 등을 계층적 구조로 저장·관리하는 중앙 데이터베이스이다.<br>
LDAP를 이용하면 예를 들어 '이름=철수', '부서=회계팀'과 같은 조건으로 사내 LDAP 서버에서 사용자의 이메일 주소 등 정보를 빠르게 조회할 수 있다.<br>

__LDAPS(LDAP over SSL/TLS)__ 는 여기에 SSL/TLS 암호화 기술을 적용한 보안 버전으로, TCP 636번 포트를 사용한다.<br>
SSL과 TLS는 통신 데이터를 암호화해 도청이나 위변조를 방지하며, 현재는 TLS가 표준으로 사용된다.<br>

__SMB(Server Message Block)__ 는 원격 서버의 파일·폴더·프린터 등 자원을 실제로 이용할 수 있게 하는 프로토콜로, TCP 445번 포트를 사용한다.<br>
LDAP가 사용자·자원 정보를 찾는 역할이라면, SMB는 그 정보를 기반으로 실제 자원에 접근·이용하는 역할을 한다.<br>
두 프로토콜은 특히 윈도우 서버의 액티브 디렉터리 환경에서 긴밀히 연동되어 사용자 인증과 자원 공유 등 핵심 네트워크 서비스를 제공한다.<br>

# 5.3 원격 접속 프로토콜

__텔넷(Telnet)__ 은 TCP 23번 포트를 사용하는 원격 접속 프로토콜로, 사용자가 CLI 환경에서 원격 서버나 장비에 명령을 입력하고 실행 결과를 확인할 수 있게 해준다. <br>
하지만 통신 데이터가 암호화되지 않아 보안에 취약하다는 문제가 있어, 현재는 거의 사용되지 않는다. 다만 네트워크를 통하지 않는 초기 장비 설정(예: 라우터, 스위치)에서는 여전히 활용된다.<br>

__SSH(Secure Shell)__ 는 텔넷의 보안 문제를 해결한 프로토콜로, TCP 22번 포트를 사용하며 모든 통신 과정을 암호화 채널로 보호한다. <br>
SSH는 공개키 인증 방식을 사용해 높은 보안성을 제공하고, 리눅스·맥OS뿐만 아니라 최근에는 윈도우에서도 기본적으로 지원된다. 이를 통해 안전하게 원격 시스템을 제어할 수 있다. <br>

__RDP(Remote Desktop Protocol)__ 는 TCP 3389번 포트를 사용하는 GUI 기반 원격 제어 프로토콜로, 사용자가 마우스와 키보드로 원격 윈도우 시스템을 완전히 제어할 수 있게 한다. <br>
마이크로소프트가 개발한 독점 프로토콜로, 원격 컴퓨터는 윈도우여야 하지만 클라이언트는 다양한 OS에서 접속 가능하다.

# 5.4 파일 전송 프로토콜

__FTP(File Transfer Protocol)__ 는 네트워크를 통해 파일을 업로드·다운로드하거나 관리하기 위한 오래된 프로토콜로, TCP 기반의 21번(제어용)과 20번 또는 동적 포트(데이터용)을 사용한다.<br>
사용자는 FTP 클라이언트(예: 파일질라)를 통해 원격 서버에 접속해 파일 전송, 삭제, 이름 변경, 권한 수정 등 다양한 파일 관리 작업을 수행할 수 있다.<br>
FTP에는 두 가지 전송 모드가 있다.
- 액티브 모드: 서버가 클라이언트에 데이터 연결을 설정 (포트 20 사용)
- 패시브 모드: 클라이언트가 서버에 데이터 연결을 설정 (동적 포트 사용, 방화벽 호환성 높음)

현재는 통신 데이터(계정, 비밀번호, 파일 내용 등)가 암호화되지 않아 보안에 취약하기 때문에, FTP 대신 FTPS나 SFTP 같은 보안 프로토콜을 주로 사용한다.<br>

__SFTP(Secure File Transfer Protocol)__는 SSH 기반의 보안 파일 전송 프로토콜로, 클라이언트와 서버 간의 모든 데이터를 암호화해 안전하게 파일을 주고받는다. <br>
FTP와 동일한 기능(업로드, 다운로드, 파일 관리 등)을 제공하지만, 전송 과정 전체가 암호화된 SSH 채널 위에서 이루어지며, TCP 22번 포트를 사용한다. <br>
대부분의 파일 전송 프로그램(예: 파일질라)은 FTP와 함께 SFTP 연결도 지원한다. 보안이 필요한 환경에서는 FTP 대신 SFTP가 표준적으로 사용된다.<br>

__TFTP(Trivial File Transfer Protocol)__는 간단한 파일 전송만을 위한 최소 기능 프로토콜로, UDP 69번 포트를 사용한다. <br>
인증 절차나 디렉터리 탐색, 파일 목록 조회, 삭제 등의 기능이 없으며, 파일 경로를 정확히 알아야 전송이 가능하다. <br>
대신 구현이 단순하고 빠르기 때문에, 네트워크 부팅, 장비 펌웨어 업데이트, 구성 파일 백업 등 자동화된 시스템 간 파일 전송에 주로 사용된다.<br>

# 5.5 이메일 프로토콜

__SMTP(Simple Mail Transfer Protocol)__ 는 이메일을 발송하고 메일 서버 간에 전송하는 역할을 하는 프로토콜로, TCP 25번 포트를 사용한다. <br>
이메일은 발신자(A)의 메일 프로그램에서 SMTP를 통해 A의 메일 서버로 전송된 뒤, 릴레이 과정을 거쳐 수신자(B)의 메일 서버에 전달된다. 다만, B의 메일 프로그램으로 직접 전송하지는 않으며, 수신자는 POP3나 IMAP 프로토콜을 사용해 자신의 메일 서버에서 메일을 확인한다.<br>

보안을 강화한 __SMTPS(SMTP Secure)__ 는 SSL/TLS 암호화를 적용한 SMTP 버전으로, 계정 정보와 메일 내용을 암호화해 안전하게 전송한다. 일반적으로 TCP 465번 포트를 사용하며, 이메일 클라이언트(예: 아웃룩)에서는 SSL/TLS 설정과 사용자 인증 기능을 함께 사용하는 것이 권장된다.<br>

__POP3(Post Office Protocol v3)__ 는 메일 서버의 이메일을 사용자 컴퓨터로 다운로드한 후 서버에서 삭제하는 방식으로, TCP 110번 포트를 사용한다.<br>
이메일이 로컬 저장소에만 남기 때문에 다른 장치에서는 확인이 불가능하고 SSL/TLS 암호화를 적용한 POP3S(포트 995)로 보안을 강화할 수 있다.<br>
한 장치에서만 메일을 관리하거나, 오프라인 환경에서 사용하기 적합하다.<br>

__IMAP(Internet Message Access Protocol)__ 은 이메일을 서버에 저장한 채로 관리하며,TCP 143번 포트를 사용한다.<br>
모든 장치와 메일 상태(읽음, 삭제, 폴더 구성 등)가 실시간 동기화되어 여러 장치에서 동일한 상태의 메일을 확인할 수 있다.<br>
SSL/TLS 암호화를 적용한 IMAPS(포트 993) 사용을 권장한다.<br>

# 5.6 웹 브라우저 프로토콜

__HTTP(HyperText Transfer Protocol)__ 는 웹 브라우저와 서버 간의 데이터 통신에 사용되는 프로토콜로, TCP 80번 포트를 사용한다.<br>
웹 브라우저가 웹 페이지를 요청(HTTP Request)하면, 서버는 HTML, CSS, JS 파일 등을 응답(HTTP Response)으로 전송하고, 브라우저는 이를 렌더링해 화면을 구성한다.<br>

하지만 HTTP는 데이터를 암호화하지 않아 보안에 취약하다. 이를 개선한 **HTTPS**는 SSL/TLS 암호화를 적용한 HTTP로, TCP 443번 포트를 사용한다.<br>
HTTPS는 통신 데이터를 암호화해 개인 정보 보호와 사이트 신뢰성을 보장하며, 현재 대부분의 웹사이트가 HTTPS를 표준으로 사용한다.<br>

서버는 요청 처리 결과를 HTTP 상태 코드로 응답한다. 주요 코드는 다음과 같다:
- 200 OK: 요청 성공
- 301 Moved Permanently: URL이 영구적으로 변경됨
- 400 Bad Request: 요청 형식 오류
- 403 Forbidden: 접근 권한 없음
- 404 Not Found: 요청한 페이지 없음
- 500 Internal Server Error: 서버 내부 오류
- 503 Service Unavailable: 서버 일시 중단(과부하·점검 등)
