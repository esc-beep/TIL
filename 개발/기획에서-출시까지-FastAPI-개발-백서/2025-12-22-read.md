# 1. 우리가 만들 프로젝트와 도구 이해

## 1.1 프로젝트를 만들고 운영해야 하는 이유

신입이거나 경력이 짧아 포트폴리오가 부족할 때는 어덯게 차별화되는 포트폴리오 프로젝트를 갖추어야 할지 막막해 한다. 

그렇다면 차별성 있는 포트폴리오란 무엇일까요? 일단 출시해서 운영했다는 점 자체가 확실한 차별성이다. 출시해서 운영했으니 사용자가 존재하기 때문.<br>
하지만 가장 뚜렷하게 차별화되는 것은 바로 나 자신이 녹아들고 드러나는 프로젝트이다.

프로젝트를 만드는 과성에서도 A 방법으로 해결하는 것이 결코 당연하지 않다.<br>
설령 모두가 A 방법으로 해결했다 할지라도 그 해결 방법에 이르기 전 단계인 문제 정의는 사람마다 다르다.

이상적인 것은 우리가 프로젝트를 만들며 자신을 인지하고 '나답게' 작업하며 나를 프로젝트에, 프로젝트 개발 과정에 녹여 내는 것이다.

많은 토이 프로젝트가 만드는 데만 목표를 두기 때문에 `localhost:8000`에서 구동해 보는 것에서 그친다.<br>
프로젝트를 출시하여 운영하는 것이 차별점인 이유는 운영할 때 자신을 투영할 여지가 많기 때문이다.<br>
개발 과정에서 중요하게 설정한 기능이나 사용자 경험이 실제 서비스 운영 과정에서는 그다지 유효하게 동작하지 않는 경험을 하는 경우가 많다.<br>
이런 피드백은 대부분 운영하며 사용자한테서 획득한다. 사용자가 어떤 것을 원하는지 알 수 없어 전부를 개발할 수는 없지만, 일찍 출시하여 상요자 피드백을 받아 원하는 방향으로 개발해 나가는 것은 충분히 가능하다.

사용자 피드백 중에는 서화해 낼 수 있을지 여부가 불분명한 것이 많아 하나하나가 도전 요소였다.<br>
하지만 어떻게든 구현을 해내는 과정에서 크게 성장할 수 있었고, 사용자 피드백에 근거한 구현이었기에 구현에 대한 사용자 반응은 보상으로 되돌아왔다.

토이 프로젝트는 최소한 내게 필요한 기능성을 제공하거나 앞서 이야기했듯이 포트폴리오 확보, 아니라면 스스로 학습하는 데 목적을 두는 것이 좋다.<br>
무엇이 목적이든 일단 개발을 완료하고 최종 목표는 출시 후 운영하는 것에 두자.

## 1.2 FastAPI를 사용하는 이유

FastAPI는 파이썬으로 작성한 비동기 경량 웹 애플리케이션이다.<br>
고성능 웹 프레임워크인 Starlette와 웹 서버 기반 처리를 고성능 데이터 도구인 Pydantic으로 데이터 처리를 한다.

웹 프레임워크: 애플리케이션을 만들기 위해 반복적으로 필요한 기능들을 표준화해 제공하는 소프트웨어 틀<br>
HTTP 요청·응답 처리, 라우팅, 미들웨어, 데이터 파싱, 인증 등의 기능들이 포함되어 있다.

그 중에서 **Starlette**은 비동기 서버 게이트웨이 인터페이스(ASGI)를 기반으로 한 웹 프레임워크이며, 빠른 속도와 높은 병렬 처리 능력이 특징이다.<br>
그리고 FastAPI는 Starlette을 기반으로 한 웹 애플리케이션 서버이다.

참고 자료: https://wikidocs.net/229721

<br>

Pydantic: Python 기반의 데이터 유효성 검사 및 설정 관리를 위한 라이브러리<br>
즉, 타입 힌트를 기반으로 데이터 구조를 모델로 정의하고 외부 입력 데이터를 자동 검증·변환하며 안전하게 dict/JSON으로 바꿀 수 있게 해주는 Python 라이브러리다.

우리가 주로 사용하는 웹 프로토콜은 HTTP 1.1로 클라이언트와 서버 간 데이터는 문자열(= 텍스트)이다. 숫자 문자열을 전송하면 이를 int로 변환하는 것이다.<br>
Starlette에는 데이터 검증 기능이 없기 때문에 HTTP 응답을 한 뒤 Pydantic을 이용해 데이터 검증을 하는 방식으로 자주 함께 사용된다.

참고 자료: https://wikidocs.net/226652

<br>

자료형 각주는 자료형 힌트로 활용된다.

```
def add(a: int, b: int) -> int:
    return a + b

```
이 코드에서 `a: int`, `b: int`, `-> int`로 각 인자의 자료형이 무엇인지, 결과는 어떤 자료형으로 나오는지 **자료형 각주**로 표시된다.

<br>

지금까지 정리한 내용을 FastAPI와 연결해보자.

Starlette은 ASGI 기반 비동기 웹 프레임워크로, HTTP 요청과 응답 처리만 담당하며 데이터 검증 기능은 제공하지 않는다.<br>
HTTP 요청을 통해 전달되는 외부 데이터는 타입이 보장되지 않기 때문에 애플리케이션 내부에서 안전하게 사용하려면 검증과 변환이 필요하다.

Pydantic은 Python의 타입 힌트를 기반으로 외부 입력 데이터를 검증하고 타입이 명확한 객체로 변환하는 라이브러리다.

FastAPI는 함수 시그니처에 작성된 타입 힌트를 해석하여 Pydantic을 자동으로 호출하고, 그 결과를 Starlette 기반 엔드포인트에 주입함으로써 HTTP 처리와 데이터 검증을 자연스럽게 연결한다.<br>
그렇기 때문에 FastAPI를 `Type annotation * (Starlette + Pydantic)`이라고 표현할 수 있다.

그리고 FastAPI는 Python에 가까운 구현이 되어 있고, Pydantic 기능을 이용해 편리한 문서화가 가능하며, 작업한 문서화 문자열은 FastAPI가 자동을 웹에서 내용을 보고 API를 시험해 볼 수 있는 기능을 OpenAPI 3 명세 기능과 ReDoc 명세 기능을 제공한다.

- Pydantic: 데이터 구현체
- SQLAlchemy: ORM
    - ORM(Object–Relational Mapping): 데이터베이스의 테이블을 프로그램의 객체로 매핑하여 SQL 대신 객체 조작으로 데이터를 다루게 해주는 기술
- SQLModel: DB에서 가져온 데이터는 SQLAlchemy 모델 객체를 Pydantic 모델 객체로 변환해야 하는 과정에서 사용됨
- Alembic: 데이터베이스 마이그레이션 도구, 새로 추가된 속성에 대응하는 테이블 열을 테이블에 추가함. SQLAlchemy 짝꿍
- pytest: 파이썬 테스트 프레임워크
- SQLAdmin: SQLAlchemy 모델 기반 어드민 도구 구축
- Sentry: 오류 수집 및 관리, 모니터링

# 2. 셸 기본 기능 익히기

사용자가 컴퓨터를 사용하면 다음과 같이 동작한다.
1. 컴퓨터 구동
2. 부트로더에서 커널 적재
3. 사용자가 셸 입력
4. 셸이 커널에 처리 요청 후 처리 완료
5. 출력

- 커널: 하드웨어와 소프트웨어 사이에 위치하여 소프트웨어 요청에 맞추어 하드웨어를 제어하는 것
- 부트로더: 운영체제의 또 다른 한 종류, 하드웨어가 켜질 때 커널이 동작하도록 필요한 조치를 함. 부트로더가 없으면 하드웨어는 동작하지만 커널은 동작하지 못하기 때문에 운영체제 구동 X
- 셸: 커널과 사용자 사이에서 사용자 명령을 커널에 전달하는 역할, GUI로 그래픽으로 나타나거나 CUI로 명령어 형태로 나타냄

경로: 컴퓨터 시스템 내에서 파일이나 폴더의 위치를 나타내는 방법
- 최상위 경로(루트): 모든 경로의 시작점 또는 시작 위치
- 절대 경로: 파일이나 디렉터리의 경로를 루트 디렉터리부터 시작하여 나타내는 것
- 상대 경로: 특정 위치를 기준으로 경로를 나타내는 것
- 홈 경로: 특정 사용자의 개인적인 작업 공간을 가리키는 것

# 3. 실습 환경 준비

1. visual studio code 설치
    - `cmd + shift + P`: 명령어 팔레트
    - focus terminal: 작업 기준 디렉터리를 시작 경로로 하여 열리는 터미널 (단축기 `ctrl + shitf + '`'`)
2. 파이썬 가상 환경
    - 의존성 충돌 방지, 프로젝트 이식성 보장(requirements.txt), 시스템 파이썬 환경 보호
    - `python -m venv .venv`: 파이썬 가상 환경 생성
    - `source .venv/bin/activate`: 파이썬 가상 환경 활성화
3. FastAPI 설치
    - `pip install "fastapi[all]"`
4. 패키지 관리자 Poetry 설치
    - `pip install poetry` 후 `poetry init`으로 초기화

# 4. 약속 잡기 서비스 기획

서비스 개요: 주최자가 제공하는 약속 시간대를 손님이 선택하여 약속을 잡는 서비스 (커피챗 용도)

주요 기능
- 캘린더 구현: 원하는 일자 선택하기
- 부킹 생성: 일정 등록하기
- 사용자별 캘린더 구분해서 보기
- 구글 캘린더 연동하기
- 소셜 로그인 구현하기

개체 관계 다이어그램(ERD): 데이터베이스 구조를 시각적으로 표현하는 방법
- 개체: 정보를 다루는 고유한 대상의 단위, 관계형 데이터베이스에서는 테이블
- 속성: 개체의 특성, 관계열 데이터베이스에서는 열
- 관계: 개체 간 관계를 나타내는 것, 1:1, 1:N, N:M이거나 정말 관계를 서술
- 기본키(PK): 개체에 대응하는 테이블에 존재하는 식별자, 테이블에 유일하게 존재하여 개별 데이터를 구분하고 식별하는 데 사용되며 id라는 이름을 사용함
- 외래키(FK): 다른 테이블에 잇는 기본키를 참조하는 키, 다른 테이블의 데이터를 참조하는 방식으로 무결성을 보장함
