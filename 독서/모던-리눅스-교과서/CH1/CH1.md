# 1장. 리눅스 소개

## 모던(현대적인) 환경이란 무엇인가

이 책에서 '모던'이란 클라우드 컴퓨팅부터 라즈베리 파이에 이르는 모든 것을 의미할 수 있다.

- 모바일 디바이스: 리눅스의 변형인 안드로이드OS 탑재
- 클라우드 컴퓨팅
- (스마트) 사물인터넷
- 프로세서 아키텍처의 다양성: x86, ARM, RISC-V + 다중 아키텍처 프로그래밍 언어(Go, Rust)

<br>

이 모든 상황을 일컬어 모던 환경이라고 정이할 수 있다. 전부는 아니더라도 대부분은 리눅스에서 실행되거나 어떤 형태로든 리눅스를 사용한다.

<br>

## 운영체제는 왜 필요한가

운영체제는 메모리 관리, 인터럽트 관리, I/O 디바이스와의 통신, 파일 관리, 네트워크 스택 구성과 관리 등 모든 무거운 작업을 수행해 다양한 하드웨어 구성 요소를 추상화하고 리눅스 커널 같은 API를 제공한다.<br>
일반적으로 OS가 공개갛는 API를 일컬어 System Call, 줄여서 syscall이라고도 부른다.<br>
Go, Rust, Python, Java 등의 고급 프로그래밍 언어는 시스템 콜 위에 빌드되며, 시스템 콜을 감싼 라이브러리가 제공된다.<br>
이 모든 것을 통해 리소스를 직접 관리하지 않고 비즈니스 로직에 집중할 수 있으며, 앱을 실행하고자 하는 다양한 하드웨어도 관리할 수 있다.

<br>

## 리눅스 배포판

리눅스 배포판이란 커널과 관련 구성 요소의 전체 번들을 의미하며, 여기에는 패키지 관리, 파일시스템 레이아웃, init 시스템, 사용자가 미리 선택한 셸이 포함된다.<br>
커널을 다운로드하고 컴파일한 후 패키지 관리자를 선택하는 등의 작업을 수행해 직접 고유한 배포판을 생성할 수 있지만, 패키징을 개인이나 기업 전문가에게 맡기고 그 결과로 나온 리눅스 배포판을 사용하는 것이 시간을 절약하는 방법이다.<br>
리눅스 배포판의 범위를 살펴보려면 [DistroWatch](https://distrowatch.com/) 사이트를 살펴보면 좋다.

<br>

## 리소스 가시성

리눅스는 유닉스의 전통을 따라 기본적으로 리소스의 전역 보기(global view)를 지원한다.<br>
유닉스와 확장 리눅스에서 거론되는 **"모든 것이 파일 - everything is a file -"**이라는 말처럼 리소스란 스프트웨어 실행을 지원하는 데 사용할 수 있는 모든 것으로 간주한다.<br>
여기에는 하드웨어와 그 추상화(CPU, RAM, 파일 등), 파일시스템, 하드 디스크 드라이브(HDD), SSD, 프로세스, 디바이스나 라우팅 테이블 같은 네트워킹 관련 항목, 사용자를 나타내는 자격증명이 포함된다.

리눅스에서 cat /proc/cpuinfo | grep "model name" 명령어를 통해 CPU 정보를 출력할 때, 다른 사용자로 로그인해도 동일한 수의 CPU를 볼 수 있다.<br>
이유는 /proc/cpuinfo가 커널이 인식한 시스템의 CPU 정보를 보여주는 가상 파일이기 때문이다. CPU는 시스템 전체 자원이므로 사용자 계정마다 다르게 보이지 않는다.

사용자 troy가 /tmp/myfile 아래에 파일을 생성할 수 있는 권한이 있고, 해당 디렉터리에 파일을 생성했다면 다른 사용자인 worf가 해당 파일을 보거나 쓸 수 있을까?<br>
상황에 따라 다르다. Linux에서는 파일 접근 권한이 디렉터리 권한과 파일 자체 권한에 따라 달라진다.<br>
worf가 디렉터리 권한과 파일에 대한 작성 권한을 가지고 있다면 troy가 생성한 파일을 보거나 쓸 수 있을 것이다.

리눅스는 프로세스 ID(PID)를 사용해 프로세스를 식별한다.<br>
동일한 PID를 가진 프로세스가 리눅스에 여러 개 있을 수 있을까?<br>
대답은 그렇다이다. namespace라는 서로 다른 컨텍스트에는 동일한 PID를 가진 여러 프로세스가 있을 수 있다. 이러한 상황은 도커나 쿠버네티스에서 앱을 실행할 때와 같이 컨테이너화된 설정에서 발생한다. (CPU 정보 또한 cgroup 등으로 격리된 환경에서는 다르게 출력될 수 있다.)<br>
모든 프로세스는 PID 1은 사용자 공간 프로세스 트리의 루트용으로 예약되어 있다.

여기서 중요한 점은 CPU와 파일처럼 주어진 리소스의 전역 보기, 프로세스 예제처럼 로컬 또는 가상화된 보기가 존재한다는 것이다.<br>
리눅스의 모든 것은 기본적으로 전역이 아니다. 먼저, 여러 사용자나 프로세스가 병렬로 실행된다는 환상은 리소스에 대한 (제한된) 가시성에서 일부 비롯된다. 리눅스에서 리소스에 대한 로컬 보기를 제공하는 방법은 네임스페이스를 통하는 것이다.<br>
또한 독립적인 차원이란 격리를 뜻한다. 리눅스에서는 cgroup이라는 커널 기능을 사용해 격리를 제공한다.
