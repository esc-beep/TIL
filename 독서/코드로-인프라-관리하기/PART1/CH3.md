# CHAPTER 3 인프라 플랫폼

## 3.1 인프라 시스템의 구성 요소

클라우드 인프라를 세 가지 플랫폼 계층으로 그룹화할 수 있다.
- 애플리케이션: 조직과 사용자에게 기능을 제공한다.
    - 다른 항목들은 애플리케이션 계층을 활성화하기 위해 존재한다.
    - 예: 애플리케이션 패키지, 컨테이너 인스턴스, 서버리스 코드
- 애플리케이션 런타임: 애플리케이션 계층에 서비스와 기능을 제공한다.
    - 서비스형 플랫폼(Paas)라고도 한다.
    - 예: 컨테이너 클러스터, 서버리스 환경, 애플리케이션 서버, OS, 데이터베이스
- 인프라 플랫폼: 인프라 리소스 및 인프라를 관리하는 도구와 서비스 모음
    - Iaas라고도 불린다.
    - 예: 컴퓨팅, 스토리지, 네트워킹 기본 요소를 포함한 인프라 리소스

<br>

## 3.2 동적 인프라 플랫폼

동적 플랫폼은 API를 사용하여 리소스를 온디맨드 방식으로 프로비저닝하고 변경할 수 있어야 한다.<br>
예전에는 인프라가 하드웨어만을 의미했지만 가상화를 통해 운영 중인 하드웨어에서 시스템을 분리했고, 클라우드는 가상 리소스를 관리하기 위해 API를 추가했다.

<br>

멀티 클라우드를 이해하기 위해서는 다음과 같은 용어를 알아야 한다.
- 하이브리드 클라우드: 프라이빗 인프라와 퍼블릭 클라우드 서비스를 함께 사용해 애플리케이션을 제공하는 방식
- 클라우드 애그노스틱: 다른 퍼블릭 클라우드 플랫폼에서 실행될 수 있도록 시스템을 구축하는 것, 벤더에 종속되는 lock-in을 방지하기 위함
- 폴리 클라우드: 둘 이상의 퍼블릭 클라우드에 여러 개의 애플리케이션과 서비스를 운영하는 방식

<br>

## 3.3 인프라 리소스

인프라 플랫폼에서 제공하는 기본적인 인프라 리소스(= 컴퓨팅, 스토리지, 네트워킹)을 묶어 premitive라고 한다. 인프라 premitive는 서비스형 DB, 로드 밸런싱, DNS, ID 및 액세스 권한 관리, 비밀 정보 관리 등의 복합 리소스로 결합할 수 있다.

<br>

### 3.3.1 컴퓨팅 리소스

- 가상 서버(가상 머신)
- 물리 서버 (= 베어메탈)
- 서버 클러스터 (AWS Auto Scaling Group 등)
- 컨테이너
- 애플리케이션 호스팅 클러스터 (ECS, EKS. AKS, GKE 등)
- 서비스형 함수 서버리스 코드 런타임

<br>

### 3.3.2 스토리지 리소스

- 블록 스토리지(가상 디스크 볼륨)
- 오브젝트 스토리지
- 네트워크 파일시스템(공유 네트워크 볼륨)
- 구조화된 데이터 스토리지
- 비밀 정보 관리

<br>

### 3.3.3 네트워킹 리소스

제로 트러스트 보안 모델은 시스템의 모든 서비스, 애플리케이션과 여러 리소스를 가장 낮은 레벨에서 보호한다. 이는 기존의 경계 기반 보안 모델이 네트워크 내의 모든 장치를 신뢰할 수 있다는 것과 반대된다.<br>
제로 트러스트 보안 모델은 명시적으로 필요한 권한과 액세스 권한만 갖는 최소 권한 원칙을 따르며, 보호가 필요한 특정 리소스에 대해 더 작은 범위의 장벽과 제어를 적용해 광범위한 신뢰 영역을 허용하지 않는다.
- 네트워크 주소 블록(VPC)
- 도메인 이름
- 라우터
- 게이트웨이
- 프록시
- API 게이트웨이
- VPN
- 전용 연결
- 네트워크 접근 규칙(방화벽 규칙)
- 비동기 메시지(= 큐)
- 캐시
- 서비스 메시: 분산 시스템의 부분 간 연결을 동적을 관리하는 분산 서비스 네트워크, 네트워킹 기능을 인프라 계층에서 애플리케이션 런타임 계층으로 이동시킴
