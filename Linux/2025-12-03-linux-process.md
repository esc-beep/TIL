# Ch 02. 프로세스 관리

## 프로세스 구성요소의 이해

- 프로세스: 실행 중인 프로그램
- 프로세스 디스크립터: 프로그램 진행 상태를 완전하게 나타내는 자료구조의 집합
    - 실행 중인 프로그램 코드, 열린 파일, 지연된 시그널 리소스, 내부 커널 데이터, 프로세서 상태, 주소 공간 등
    - 커널 영역에서 프로세스 별로 해당 프로세스를 관리하기 위한 프로세스 디스크립터 자료 구조가 유지됨

- 쓰레드: 프로세스 내의 실행 흐름
    - 프로세스 당 최소 1개 이상의 쓰레드가 존재함
    - 리눅스에서는 경량 프로세스라고도 부르며, 쓰레드 단위로 스케줄링됨
    - 스케줄러는 쓰레드별로 스케줄링을 해서 컨텍스트 스위칭(쓰레드 간 교환)을 통해 CPU에 해당 프로세스를 실행함
- 쓰레드는 주소 공간이나 열린 파일 등 여러 자원을 공유할 수 있음
    - 공유 자원을 접근할 때 서로 동기화해야 함
- 리눅스 커널 입장에서는 쓰레드와 프로세스가 동일하게 취급됨

- PID: 커널이 각 프로세스에 고유한 ID를 부여한 것, 프로세스가 생성되는순서대로 배정됨
- PPID
    - 리눅스에는 새 프로그램을 시작하는 시스템 콜이 없고, 기존 프로세스를 복제 및 프로그램을 교체하는 방식으로 이루어짐
    - 기존 프로세스는 새로운 프로세스를 생성하고 자신을 복제함. 복제된 프로세스는 현재 실행중인 프로그램을 교체함
    - PPID는 그 프로세스를 복제한 부모의 PID

- niceness: 프로세스 스케줄링의 우선순위를 결정함
- 우선순위가 높다 = CPU 사용 시간이 많다
- nice 값의 범위: -20 ~ +19, nice 값이 작을수록 우선순위가 높음
    - CPU 성능 향상과 CFS 스케줄러(균등한 시간 분배), I/O 요청(CPU 대기 시간)으로 인해 우선순위 조정에 따른 차이가 극적으로 나타나지는 않음
    - 대부분의 경우 기본값을 사용함

## 프로세스 라이프 사이클의 이해

신규 프로세스 생성
1. fork 시스템 콜로 자신을 복제
    - 자식: PID 0 리턴, 부모: 새로 생성된 자식의 PID 리턴
2. 자식은 새 프로그램의 실행을 위해 exec 계열의 함수를 호출해 현재 실행하고 있는 프로그램을 다른 것으로 교체함

자식 프로세스 종료
- wait 계열 시스템 콜을 호출해 부모가 자식 프로세스의 종료 결과를 확인한 후에만 프로세스 상태 정보(프로세스 디스크립터)를 삭제할 수 있음
- 부모가 자식보다 먼저 죽는 경우, 커널은 예정된 wait이 없다는 것을 인지
    - 고아 프로세스를 init process(systemd)의 자식으로 설정
    - 자식 프로세스 종료를 위해 필요한 wait 동작을 수행함

프로세스 상태
- TASK_RUNNING: 프로세스가 실행 가능한 상태, 현재 실행 중 또는 실행 큐에 실행 대기 상태
- TASK_INTERRUPTIBLE: 틀정 조건을 기다리며 프로세스가 대기 또는 중단되어 있는 상태, 기다리는 조건이 발생 또는 시그널을 받으면 실행 가능 상태로 이동
- TASK_UNINTERRUPTIBLE: TASK_INTERRUPTIBLE과 동일한 상태지만, 시그널을 받아도 깨어나지 않음. 프로세스가 다른 방해를 받지 않고 반드시 대기해야 하는 경우 사용됨
- TASK_ZOMBIE: 프로세스가 중단되었지만 부모 프로세스가 wait 시스템 콜을 호출하지 않은 상태

프로세스 상태 모니터링
- ps: 프로세스와 관련된 주요 지표들을 표시
    - PID, UID, 우선순위, 컨트롤 터미널, 프로세스별 메모리 크기, 소비한 CPU 시간, 현재 상태(실행 중/중지/대기 중)
    - `ps aux`: 실행 중인 모든 프로세스에 대한 정보를 표시
        - a: 모든 프로세스, u: 사용자 지향적 출력, x: 터미널이 없는 프로세스도 표시
    - `ps lax`: 실행 중인 모든 프로세스 정보를 표시
        - l: long 상태로 출력
        - UID를 사용자명으로 변환하지 않고 ID로 표시하여 보다 가볍게 동작함
    - `ps aux | grep <명령어>`: <명령어>에 대한 프로세스 정보 확인
    - `ps auxf`: 자식 프로세스를 트리 형식으로 표시
- top: 특정 기간(디폴트 3초) 동안 수집한 리눅스 프로세스 정보를 지속적으로 제공하는 도구
    - 가장 CPU를 많이 사용하는 프로세스를 화면의 맨 위에 배치
    - 화면 상단에는 시스템 상태의 요약 정보를 제공
    - `htop`은 스크롤이 가능하고 full 커맨드라인 정보를 제공하는 등 더 나은 인터페이스를 제공함

프로세스 종료
- `kill [-signal] pid` 명령을 통해 프로세스 종료 관련 시그널 전송
- 주요 시그널
    - `SIGTERM [15]`: 실행을 완전하게 종결하라는 요청, 프로세스가 시그널 수신(처리/차단) 가능
    - `SIGKILL [9]`: 차단 불가능하며, 프로세스를 커널 수준에서 종료, 프로세스가 시그널을 수신할 수 없음, 자원 정리 작업 실행 X
    - `SIGINT [2]`: 터미널에서 ctrl+c 입력, 프로세스가 시그널 수신(처리/차단) 가능
- 프로세스 종료 방식은 kill -15로 종료해보고, kill -9를 시도하는 것을 권장함
- kill -9로도 종료가 되지 않는다면 재부팅을 실행해야 함

## proc 파일시스템의 이해

proc 파일 시스템
- 커널이 시스템 상태와 관련한 다양한 정보를 노출시키는 pseudo 파일시스템
    - 실제 파일 사이즈는 0이고 파일을 읽을 때 실시간으로 내용이 생성됨
- 운영체제가 유지하는 정보를 커널 모드가 아닌 유저 모드에서 쉽게 접근할 수 있도록 제공함
- 프로세스 정보 외에도 커널이 관리하는 다양한 상태 정보와 통계값을 제공함
- 대부분 proc 파일시스템에서 직접 데이터를 읽기보다는 ps, top, vmstat등 다양한 명령을 사용
- 프로세스와 관련된 정보
    - /proc/PID/cmdline: 프로세스가 실행하고 있는 명령이나 프로그램
    - /proc/PID/environ: 프로세스의 환경변수
    - /proc/PID/fd: 오픈된 파일 디스크립터
    - /proc/PID/exe: 현재 실행중인 파일에 대한 심볼릭 링크
    - /proc/PID/stat: 전반적인 프로세스 상태 정보(ps)
    - /proc/self: 자신의 /proc/PID로 이동
- 프로세스와 관계 없는 시스템 정보
    - /proc/cpuinfo: 프로세서 정보 (벤더와 스피드, 캐시크기, 코어등)
    - /proc/meminfo: 메모리 관리 정보
    - /proc/diskstats: 논리 디스크 장치들 정보
    - /proc/net: 네트워크 스택과 관련된 주요 정보
    - /proc/version:  커널의 버전 정보
    - /proc/uptime: 부트 이후 경과된 시간 정보
    - /proc/cmdline: 커널에 넘겨지는 부트 옵션
    - /proc/kmsg: 커널이 출력하는 메시지

## 주기적인 작업 관리

새벽에 보안 관련 도구 실행, 백업 및 미러링, 배치 작업 수행, 시스템 정보를 메일로 전송, 로그 데이터 관리 등 주기적으로 실행해야 하는 작업들이 있음

cron(cron job) : 정의된 스케줄에 따라 명령을 실행하는 도구
- cron 작업을 수행하는 데몬은 시스템 시작 시 구동되고, 계속 실행됨
- 스케줄 설정 : cron table(crontab) 파일 작성
- crontab 관리
    - `crontab -e`: 기존 crontab 항목 편집
    - `crontab -l`: crontab 리스트 출력
    - `crontab -r`: crontab 삭제
    - `crontab -e <USER_ID>`: root 사용자의 경우 USER_ID 사용자의 crontab 정보를 확인 가능함
- crontab 설정 : 분(0-59) 시(0-24) 일(1-31) 월(1-12) 요일(0-6) 명령
    - * * * * * command: 매 1분마다 명령을 실행
