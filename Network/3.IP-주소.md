# 3.1 IP 주소

**IP 주소**는 TCP/IP 모델의 인터넷 계층에서 사용하는 논리적 주소로, WAN 상의 모든 컴퓨터를 구분하기 위해 사용된다.<br>
버전 종류로는 IPv4와 IPv6가 있다.<br>

- IPv4:
    - 인터넷 초창기부터 사용된 주소 체계
    - 점으로 구분된 4부분(각 0~255) → 총 32비트(2³² ≈ 43억 개)
    - 주소 부족 문제 발생
- IPv6:
    - IPv4 주소 부족 문제 해결을 위해 도입
    - 128비트(2¹²⁸)로 훨씬 많은 주소 제공하지만 구조가 복잡

IP 주소는 네트워크 부분과 호스트 부분으로 구성된다.<br>
네트워크 부분으로 네트워크 전체를 식별하고, 호스트 부분으로 네트워크 내 개별 장치를 식별한다.<br>
같은 네트워크에 속한 장치는 네트워크 주소가 같고, 호스트 주소가 다르다.<br>
주소의 용도와 규모에 따라 클래스 로 구분된다.<br>

IPv4 주소 클래스 구분은 다음과 같이 이루어진다.<br>

<br>

루프백 주소란 127.0.0.0 - 127.255.255.255 범위의 IP 주소를 말한다. 이는 자기 자신(로컬 컴퓨터)을 가리키는 주소이며 클래스 구분과 무관하게 모두 루프백으로 사용된다.<br>
외부 네트워크로 전송되지 않고 컴퓨터 내부에서 자체 처리되므로 네트워크 연결 및 시스템의 통신 기능 테스트용으로 사용된다.<br>
localhost는 루프백 주소 중 대표 주소로, 127.0.0.1(IETF 지정 공식 루프백 기본 주소)를 의미한다.<br>

# 3.2 서브넷 마스크

**서브넷 마스크**는 IP 주소의 네트워크 부분과 호스트 부분을 구분하는 32비트 값이다. 네트워크 부분은 1, 호스트 부분은 0으로 나타낸다.<br>
클래스 A/B/C 방식은 네트워크 규모가 고정되어 비효율적이므로 서브네팅으로 네트워크를 유연하게 분할하여 조직 규모나 용도에 맞게 세밀한 네트워크를 구성할 수 있다.<br>
한 네트워크에서 호스트 부분의 모든 비트가 0인 네트워크 주소와 호스트 부분의 모든 비트가 1인 브로드캐스트 주소를 제외한 호스트 주소 수를 할당할 있다.<br>

서브넷 마스크는 `IP 주소/네트워크 비트 수`로 나타내는 CIDR 표기법으로 표기한다.<br>
예를 들어 20.10.3.4/8 은 네트워크가 8비트이므로 클래스 A(255.0.0.0)을 가리킨다.<br>

CIDR 표기법으로 사용 가능한 범위는 /8 - /30 이다.<br>
/31: 호스트 부분이 1비트뿐이라 일반 네트워크에서는 사용이 불가하고, 두 장치 간 연결인 Point-to-Point 링크에서만 예외적으로 사용한다.<br>
/32: 모든 비트가 네트워크 부분이므로 호스트가 1개뿐이라 통신이 불가하다. 독립 장치 식별용으로 이론상 존재하지만 실제로는 거의 사용되지 않는다.<br>

# 3.3 서브네팅

**서브네팅**이란 하나의 네트워크를 여러 개의 작은 네트워크로 분할하는 기술로, 호스트 부분을 빌려 네트워크 부분으로 확장하는 방식이다. <br>
서브네팅의 장점은 다음과 같다.
- 보안 강화: 네트워크에 대해 접근 권한을 제한 가능, 보안 강화
- 네트워크 성능 향상: 브로드캐스트 도메인 사이즈를 줄여 네트워크의 성능 향상
- IP 주소 낭비 개선: IP 주소 낭비를 줄이고 네트워크를 효율적으로 관리 가능
- 네트워크 문제 해결 용이: 네트워크 문제 발생 시 문제의 범위를 좁혀 원인 파악 및 해결에 용이

<br>

예를 들어, 200.100.100.0/24 네트워크를 4개의 서브넷으로 분할하면 `200.100.100.0/26`, `200.100.100.64/26`, `200.100.100.128/26`, `200.100.100.192/26`가 된다.<br>
기존에는 24비트(네트워크) + 8비트(호스트)였는데, 호스트 비트 2개를 네트워크 비트로 전환해 26비트(네트워크) + 6비트(호스트) 구조로 변경된 것이다.<br>
따라서 네트워크 비트를 2비트 추가해 슬래시 표기법이 /24에서 /26으로 변경된다.<br>
이때 호스트 비트가 전부 0인 것은 서브넷 주소이고, 호스트 비트가 전부 1인 것은 브로드캐스트 주소이므로 나머지 주소만 호스트에 할당할 수 있다.

호스트 부분에서 n비트를 빌리면 2ⁿ개의 서브넷을 생성할 수 있다. <br>
단, 항상 2비트 이상은 호스트 부분으로 남겨야 한다. 최소한 2개의 유효 호스트 주소가 있어야 네트워크를 구성할 수 있기 때문이다.<br>

# 3.4 공인 IP 주소와 사설 IP 주소

__공인 IP(Public IP)__ 는 전 세계에서 고유한 IP 주소이며 IANA가 관리 및 배정한다.<br>
인터넷에 직접 연결 가능하며 장치의 논리적 위치 정보를 포함하므로 전 세계에서 중복이 불가하다.

__사설 IP (Private IP)__ 는 개인 네트워크(LAN) 내에서만 사용 가능한 IP 주소이다.<br>
개인 LAN에서만 사용되므로 중복이 허용되며 인터넷에 직접 연결이 불가하다.<br>
CIDR 표기법으로 네트워크/호스트를 구분하며 IANA가 예약한 특정 범위만 사용할 수 있다.<br>
외부(인터넷)에서 접근하려면 게이트웨이가 목적지 장치를 지정하는 **포트 포워딩**이 필요하다.<br>
RFC 1918에 정의된 3가지 사설 IP 대역은 다음과 같다:
- 10.0.0.0/8 → 클래스 A 범위
- 172.16.0.0/12 → 클래스 B 범위
- 192.168.0.0/16 → 클래스 C 범위

<br>

NAT는 LAN 내 장치의 사설 IP를 공인 IP로 변환해 인터넷 접근을 가능하게 하는 것이다.<br>
기본 게이트웨이가 변환 역할 수행하며 여러 장치가 하나의 공인 IP를 공유해 IP 자원을 절약할 수 있다.

# 3.5 DHCP

**DHCP**는 네트워크 내 장치에 IP 주소, 서브넷 마스크, 게이트웨이, DNS 서버 주소 등을 자동으로 할당하는 프로토콜이다.<br>
네트워크 관리자가 IP를 수동으로 설정할 필요가 없어 관리 효율성이 올라가고, 유휴 IP를 재활용해 IP 부족 문제를 해결한다.<br>
DHCP는 가정용 공유기나 모뎀에 기본 내장되어 자동 설정을 지원한다.<br>
임대 시간(보통 24시간) 내 사용하며, 만료 전 갱신 요청이 가능하다.<br>


DHCP는 다음의 4단계로 동작한다.
1. Discover (탐색) – 클라이언트가 브로드캐스트로 IP 요청
2. Offer (제공) – DHCP 서버가 사용 가능한 IP 제안
3. Request (요청) – 클라이언트가 제안된 IP 사용 의사 전달
4. Acknowledge (확인 응답) – 서버가 IP 및 관련 설정 정보 확정 전송
