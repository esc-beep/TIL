## 포트폴리오 어나더레벨

참고 자료: [인프런 포트폴리오 어나더레벨](https://www.inflearn.com/course/%ED%8F%AC%ED%8A%B8%ED%8F%B4%EB%A6%AC%EC%98%A4-%EC%96%B4%EB%82%98%EB%8D%94%EB%A0%88%EB%B2%A8/dashboard)

### 합격하는 포트폴리오의 공식

1. 채용 시장의 이해
    - 부트캠프, 국비교육으로 계속 신입 개발자들이 배출되고 있고, AI의 발전으로 단순 코딩의 가치는 낮아지고 있음.
    - 면접관에게 어필하기 위해서는 증거 있는 성과가 필요함
2. 첫 장에 임팩트 주기
    - 나의 강점(수치화할 수 있는 것이라면 더 좋음)을 첫번째 장에 나타내자.
3. 자주 하는 실수
    - 신입 개발자 X
    - 10장 이상의 장문 포트폴리오 X
    - 개발 철학 같은 추상적 서술 X
    - 프로그램 버전, 장문 X
4. 집중해야 할 것
    - 문제 해결 능력(디테일하게)
        - API 서버 부하 테스트 구현 (X)
        - API 서버 부하 테스트(JMeter) 결과, 초당 요청 처리량 200 > 1200건 개선 (O)
    - 수치화된 결과
        - API 응답 속도 개선 (X)
        - 1.2s > 320ms (73% 단축) (O)

### 무엇을 보여줄 것인가

성과와 기여 중심으로 작성하기
- AWS 비용 최적화 프로젝트 담당을 하면서 **비용 30% 절감**
- Redis 캐시 도입을 하면서 서버 응답속도 __1.2s > 320ms (73% 개선)__
- Github Actions CI/CD 구축을 하면서 **배포 시간 40분 > 5분 단축**

강점 요약 + 링크
- 오픈소스 기여 > 링크를 통해 기여한 PR 보여주기
- 직군별로 포인트가 될 키워드가 다름. 백엔드는 비용, 안정성, 트래픽 중심 / 프론트엔드는 UX 중심 / DS는 모델 정확도 중심 등
- 무엇을 어디에 배치할지도 중요함. 포폴을 적을 때 소개 > 프로젝트, 경력, 학력, 커뮤니티 중 우선적으로 나타내고 싶은 것들이 있다면 먼저 놓기
- 프로젝트는 기본적으로 내림차순으로 작성할 것.

### 면접관을 사로잡는 문장의 힘

문제, 해결, 결과가 명확해야 하고, 요약해서 표현해야 한다. <br>
문제 발생 > 기술/방법을 사용하여 해결 > 개선 성과/달성 <br>
문체의 경우 함 또는 했다 중 한 가지로 통일해서 포트폴리오에 서술해야 함 <br>
구제적인 기술 명(ex. Redis-Query Cashing)을 작성하는 것은 전문성을 높여주면서 면접관의 질문을 유도할 수 있음 <br>

각 주제별 써야 하는 워딩
- 성능: 응답속도 Xs > Yx, 처리량 N배 증가
- 비용: 서버 비용 XX% 절감
- 사용자: DAU(일간 활성 사용자 수)/MAU(월간 활성 사용자 수) XX% 증가
- 안정성: 에러율 XX% > YY%
- 협업: 배포 주기 XX일 > YY일

### 기술에는 근거가 있어야 한다

프로젝트: 기간, 명수, 담당, 스킬, 링크 / 여기서 기술을 사용한 이유가 정확히 준비되어야 함
- 왜 이런 기술을 사용하셨나요? 답변 가능해야 한다.
- Trade-off를 생각하는 개발자가 되어야 한다. 기술 선택에는 항상 trade-off가 있고, 그 고민을 드러내면 면접관이 높게 평가한다.

기술의 분류
- strong(전문성 보유): 전문성 보유 > 6개월 이상 사용, 블로그 글에 깊게 아티클, 관련 오픈소스 PR
- knowledgeable(보조 지식): strong 외 1번 예제 해봄, 써본 적 있다 정도?
- 기술을 분류하면 면접관의 질문을 유도할 수 있다. 보통은 strong에 집중해서 질문하게 됨 > 내가 답변을 잘 할 확률도 올라감
- 포폴은 면접관의 질문을 이끌어내는 하나의 장치

### 합격을 결정짓는 악마의 디테일

채용 시장이 상향평준화 되어 가고 있기 때문에 기술 역량이 비슷한 지원자가 많다. <br>
결국 디테일이 합격 여부를 가르게 된다. 맞춤법, 레이아웃 정돈이 된 포폴이 꼼꼼함을 나타낸다.

사진에 신경쓰자. 이력서에 들어가는 사진은 무조건! 사진관 사진

원칙을 지킨다.
- 1장 ~ 3장 안에 요약하는 것이 원칙, 컬러는 흑백 혹은 파란색 등 차분한 톤
- 프로젝트마다 같은 포맷(문제 > 해결 > 결과)를 반복하여 가독성 높이기
- 맞춤법 관리 - 오타는 치명적인 감점 요소

### 깃헙 하나로 합격률 끌어올리는 법

- 사용 기술, 주요 기능, 소프트웨어 아키텍처, 시스템 아키텍처, 패턴 흐름도와 같이 깃헙을 관리하기
- 팀 프로젝트의 경우 내가 무엇을 담당했는지를 어필하는 것이 중요함. 깃허브를 포크해서 내가 담당한 부분만 요약해서 다시 정리하자.
- 깃허브에 정석적인 커밋 메시지로 작성하기(https://www.conventionalcommits.org/ko/v1.0.0/)
- 서비스는 유지가 되고 있어야 한다. 깃헙에서 눌렀을 때 서비스에 들어가지지 않는다면 감점, 오라클 등 무료 클라우드 서비스를 이용해서 배포하기
- 간단한 QA는 해야 한다. 404 페이지가 나오면 곤란하겠지?

### 실제 합격 사례로 배우는 포트폴리오 전략

- 대회 우승 사례, 높은 학점 사례 등 나의 강점을 이용해서 3줄로 강점을 압축해 자기소개 작성하기
- TMI는 제거해서 강점만 컴팩트하게 보일 수 있도록!
